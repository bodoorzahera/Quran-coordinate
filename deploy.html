١. نظرة عامة على النظام1. System Overview

هذا النظام يربط كل كلمة من كلمات المصحف المدني (٧٧٬٣٢٠ كلمة عبر ٦٠٤ صفحات) بإحداثيات البكسل الدقيقة لموضعها على صورة الصفحة. يتكوّن من:

  • خادم خلفي (Backend): تطبيق FastAPI بلغة Python يخدم واجهة برمجة التطبيقات (API) و واجهة المستخدم و صور الصفحات.
  • الواجهة الأمامية (Frontend): صفحة HTML/CSS/JavaScript مدمجة داخل الخادم نفسه (ليست مشروع بناء منفصل)، تعمل كتطبيق ويب تقدمي (PWA) يعمل دون اتصال.
  • قاعدتا بيانات SQLite: quran_glyphs.db (بيانات المحارف) وword_freq.db (تكرار الكلمات ومواضعها).
  • حِزم: حزمة Python على PyPI (qurancoor) وحزمة JavaScript على npm (quran-word-coords).
  • تطبيق أندرويد: ملف APK جاهز في مجلد downloads/.

الفكرة الأساسية للنشر: الخادم يخدم كل شيء — لا توجد خطوة بناء منفصلة للواجهة، وبيانات الإحداثيات وقاعدتا البيانات مرفقتان في المستودع، فيكفي الاستنساخ والتشغيل.

This system maps every word of the Madani mushaf (77,320 words across 604 pages) to its pixel-accurate bounding box on the page image. It consists of:

  • Backend: a Python FastAPI app that serves the API and the UI and the page images.
  • Frontend: HTML/CSS/JavaScript embedded inside the server itself (not a separate build), delivered as an offline-capable Progressive Web App (PWA).
  • Two SQLite databases: quran_glyphs.db (glyph data) and word_freq.db (word frequency & occurrences).
  • Packages: a PyPI package (qurancoor) and an npm package (quran-word-coords).
  • Android app: a ready APK in the downloads/ folder.

Key deployment idea: the server serves everything — no separate frontend build, and the coordinate data + both databases ship in the repo, so you just clone and run.

٣. التنزيل والتشغيل من GitHub3. Download & Run from GitHub

هذا هو المسار الأساسي لتشغيل النظام كما هو الآن بالضبط:

This is the canonical path to run the system exactly as it is now:

git clone https://github.com/bodoorzahera/Quran-coordinate.git
cd Quran-coordinate

# تثبيت الحزمة وكل اعتمادياتها / install package + all extras
pip install -e ".[all]"

# تشغيل الخادم (الواجهة + API + الصور) / start server (UI + API + images)
qurancoor serve --images-dir ./images --port 8003

# افتح المتصفح على / open in browser:
#   http://localhost:8003
📌 لا توجد خطوة بناء. بيانات الإحداثيات مرفقة داخل الحزمة، وقاعدتا البيانات quran_glyphs.db وword_freq.db داخل المستودع، فالنظام يعمل فور التثبيت. 📌 No build step. Coordinate data ships inside the package, and both quran_glyphs.db and word_freq.db are in the repo, so the system runs immediately after install.

٤. إعداد الواجهة الأمامية / Webhost4. Frontend / Webhost Configuration

الواجهة الأمامية مدمجة داخل الخادم (تُرسَل كـ HTML من server.py)، لذا لا تحتاج إلى استضافة منفصلة للواجهة. كل ضبط الواجهة يتم عبر أعلام أمر serve:

The frontend is embedded in the server (returned as HTML from server.py), so it needs no separate frontend host. All "webhost" configuration is done via serve flags:

العَلَمFlagالافتراضيDefaultالوظيفةPurpose
--images-dir./imagesمجلد صور الصفحاتpage images directory
--mushaf-dir./mushafمجلد نصوص المصحف JSONmushaf JSON directory
--word-freq-db./word_freq.dbمسار قاعدة تكرار الكلماتword-frequency DB path
--letter-stats./letter_stats.jsonملف إحصاء الحروفletter-stats file
--host0.0.0.0عنوان الاستماعbind address
--port8003المنفذport
⚠️ المنفذ يُضبط عبر العَلَم --port فقط (لا يقرأ متغيّر البيئة PORT). الاستضافات التي تحقن $PORT (مثل Render وKoyeb) يجب أن تستخدم --port $PORT في أمر التشغيل، بينما تتوقع Hugging Face Spaces المنفذ 7860. ⚠️ The port is set only via the --port flag (it does not read a PORT env var). Hosts that inject $PORT (Render, Koyeb) must pass --port $PORT; Hugging Face Spaces expects port 7860.

PWA والعمل دون اتصالPWA & offline

الخادم يقدّم /manifest.json و/sw.js (Service Worker) تلقائيًا، فيمكن تثبيت الواجهة كتطبيق وتعمل الصور والـ API بالتخزين المؤقت دون اتصال.

The server serves /manifest.json and /sw.js automatically, so the UI is installable as an app and caches images/API for offline use.

وكيل عكسي اختياري (nginx) لنطاق مخصّصOptional reverse proxy (nginx) for a custom domain

server {
    listen 80;
    server_name quran.example.com;

    location / {
        proxy_pass         http://127.0.0.1:8003;
        proxy_set_header   Host $host;
        proxy_set_header   X-Forwarded-For $remote_addr;
    }

    # تخزين مؤقت طويل للصور / long cache for page images
    location /api/image/ {
        proxy_pass http://127.0.0.1:8003;
        proxy_cache_valid 200 30d;
        add_header Cache-Control "public, max-age=2592000";
    }

    gzip on;
    gzip_types application/json text/css application/javascript;
}

5. Docker

حاوية محمولة تعمل على معظم الاستضافات. تستخدم ${PORT:-8003} لتتوافق مع الاستضافات التي تحقن المنفذ:

A portable container that runs on most hosts. It uses ${PORT:-8003} to fit hosts that inject the port:

# Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY . /app
RUN pip install --no-cache-dir ".[all]"
EXPOSE 8003
CMD qurancoor serve --images-dir ./images --host 0.0.0.0 --port ${PORT:-8003}
docker build -t qurancoor .
docker run -p 8003:8003 qurancoor

٦. أفضل ٣ حلول استضافة مجانية بدون فيزا6. Top 3 Free Hosts — No Credit Card

جميع الخيارات أدناه مجانية ولا تتطلب بطاقة فيزا (تم التحقق في يونيو ٢٠٢٦). القيد الأهم هو الصور (~511 ميجابايت)، لذا يأتي الترتيب وفقًا لملاءمته لها.

All options below are free and require no Visa/credit card (verified June 2026). The main constraint is the images (~511 MB), so ranking reflects fit for that.

🥇 Hugging Face Spaces (Docker) recommended

Best for the unified deploy: free disk up to 50 GB easily holds the images, 2 CPU / 16 GB RAM, no card. Sleeps after ~48h idle, wakes on first visit.

Deploys straight from a GitHub repo, no card, with scale-to-zero. Best if you offload images to external storage (Plan B below), since free-tier disk is limited.

٧. استراتيجية الصور (511 ميجابايت)7. Image Strategy (511 MB)

الخطة A — نشر موحّد (الأبسط)Plan A — Unified deploy (simplest)

الخادم يخدم الصور من ./images مباشرة. يحتاج إلى قرص ≥600 ميجابايت، لذا الأنسب له Hugging Face Spaces. لا حاجة لأي تعديل في الكود.

The server serves images directly from ./images. Needs ≥600 MB disk, so Hugging Face Spaces fits best. No code changes needed.

الخطة B — فصل الصور على CDN/تخزينPlan B — Offload images to CDN/storage

ارفع مجلد images/ إلى تخزين كائنات مجاني مثل Cloudflare R2 (بدون بطاقة، طبقة مجانية)، ثم وجّه روابط الصور إليه. هكذا يبقى حجم التطبيق صغيرًا فيناسب استضافات 512 ميجابايت (Render / Koyeb).

  • نقطة التعديل في الكود: المسار /api/image/{n} في src/qurancoor/server.py — استبدل إرجاع الملف المحلي بإعادة توجيه (redirect) إلى رابط الـ CDN.
  • أو على مستوى الواجهة: عدّل عنوان الصور ليشير إلى نطاق الـ CDN بدلًا من /api/image/.

Upload the images/ folder to free object storage like Cloudflare R2 (no card, free tier), then point image URLs there. This keeps the app instance tiny so it fits 512 MB hosts (Render / Koyeb).

  • Code touch point: the /api/image/{n} route in src/qurancoor/server.py — replace the local file response with a redirect to the CDN URL.
  • Or at the frontend level: change the image base to the CDN domain instead of /api/image/.
